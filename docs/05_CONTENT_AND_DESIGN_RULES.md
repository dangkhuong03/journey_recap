# Content and Design Rules — Revised

## Voice
- Reflective, specific, humble, analytical.
- Do not sound like a corporate testimonial.
- Do not turn every insight into motivational copy.
- Preserve nuance: the old engineer mindset is valuable and remains part of the identity.
- Keep the four-week internship as the main subject.

## Copy hierarchy
Prefer short visual statements for the main layer, with supporting detail below.

Strong compression directions:
- 4 WEEKS. A SHIFT IN HOW I BUILD.
- HOW DOES IT WORK? → WHY / FOR WHOM / HOW DO WE KNOW?
- VALUE BEFORE TECHNOLOGY
- EVIDENCE BEFORE ASSUMPTION
- MY INTENT → AI SUPPORT → MY DECISION
- ALIGNMENT BEFORE OPTIMIZATION
- WHAT I COMPLETED ≠ WHAT I MASTERED
- HUMAN EVALUATION × DEVELOPMENT

## Content scope
Use AI20K only as a short prologue explaining the starting mindset.
The four internship weeks must dominate the page.

Do not create an exhaustive challenge gallery.
Do not invent a “top 5 challenges” section unless the user later supplies and requests it.
Challenge references may appear as contextual learning nodes, but the story is about evolution, not project inventory.

## Achievement framing
Because the source does not provide reliable quantitative achievements, visualize achievement qualitatively through:
- broader understanding
- applied practice
- changed workflow
- changed behavior
- clearer alignment/evaluation mindset

Do not use fake counters to make the page feel infographic-like.

## Content safety
Do not invent:
- number of challenges
- number of prototypes
- number of users
- metrics
- company/private data
- mentor wording
- test scores
- precise week-by-week chronology not stated in the source

If such information is later supplied, it can be visualized.

## Visual concept recommendation
Primary metaphor: a four-week journey path containing a recursive learning/evolution loop.

The journey is not a straight “beginner to expert” progression.
It is:
Experience → Learn → Reflect → Select → Apply → Feedback → Update → Repeat.

## Aesthetic direction
Editorial + technical + reflective.

Possible visual ingredients:
- large typographic chapter markers
- four-week progression rail
- fine technical grid/lines
- restrained diagram language
- path/loop motif
- subtle annotations
- SVG process diagrams
- before/after split states
- progressive reveals
- one strong turning-point interruption around “Alignment before optimization”

Avoid a generic SaaS product aesthetic.

## Infographic behavior
Infographic does not mean “add charts.”
Prefer:
- progression
- process
- relationship
- before/after
- learning loop
- knowledge/system map
- achievement categories

Only use quantitative charts when real quantitative data exists.

## Color
Use a restrained palette with one accent family for progression/evolution.
Do not use many unrelated colors unless they encode distinct semantic categories.

## Typography
Use a strong display hierarchy for chapter statements and a highly readable body type.
Keep line length comfortable.

## Accessibility
- semantic headings
- visible focus states
- sufficient contrast
- reduced-motion support
- readable minimum body size
- do not encode essential meaning by color alone

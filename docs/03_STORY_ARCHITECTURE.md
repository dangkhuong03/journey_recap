# Proposed Story Architecture — Day-Based Journey, Cross-Cutting Learning

## Core thesis
These four internship weeks did not teach one clean topic per week. Instead, each Day/challenge exposed me to different product, business, UX, AI-system, infrastructure, evaluation, and human–AI problems. Looking back across those scattered experiences, several patterns gradually changed the way I think and build.

Do not treat this thesis as copy that must appear verbatim. Use it as the narrative test for every section.

## Scope priority
The main story is the **past four weeks of internship**, not the entire AI20K journey.

AI20K exists only to answer:
> What mindset did I enter the internship with, and why?

## Critical chronology rule
Do **not** map one learning theme to one week.

The internship content was distributed across individual Days/challenges. Technical, product, UX, business, evaluation, and human–AI learning appeared interleaved throughout the four weeks.

Therefore:
- time should be represented as a continuous **Day 1 → Day 27 / four-week timeline**,
- challenge categories may be layered onto that timeline,
- learning principles should be extracted **after looking across the whole journey**,
- mentor feedback should be treated as a later turning point, not as “Week 4 = Realign”,
- do not fabricate an artificially clean weekly curriculum.

## Visual transformation line
STARTING MINDSET
ENGINEERING CURIOSITY + EARLY PRODUCT THINKING

→ FOUR WEEKS / MANY DIFFERENT PROBLEMS

→ REPEATED RESEARCH / BUILDING / TESTING / REFLECTION / FEEDBACK

→ EVOLVED WAY OF BUILDING
VALUE + EVIDENCE + HUMAN JUDGMENT + ALIGNMENT + EVALUATION

## Recommended 9-section architecture

### 01 — Hero / Four Weeks, One Shift
Purpose: establish the assignment context and transformation in <= 5 seconds.

Recommended direction:
- four weeks of internship,
- many different challenge types,
- one gradually evolving way of thinking and building.

Possible headline direction:
> 4 TUẦN. NHIỀU BÀI TOÁN. MỘT CÁCH TƯ DUY LIÊN TỤC ĐƯỢC CẬP NHẬT.

Possible transformation cue:
HOW DOES IT WORK?
→ SHOULD IT BE BUILT?
→ FOR WHOM?
→ WHAT EVIDENCE SUPPORTS IT?
→ HOW SHOULD HUMANS EVALUATE IT?

Visual idea:
A continuous Day-based path that grows richer as new challenge categories and learning patterns appear.

### 02 — Prologue / The Mindset I Entered With
Keep this concise.

Show:
- Software Engineer background,
- curiosity about technology and algorithms,
- joining AI20K expecting deeper AI and originally choosing Application,
- shift toward AI Business & Product after learning to ask about value, users, validation, metrics, and evaluation.

Key framing:
The engineer mindset was expanded, not discarded.

Visual compression:
ENGINEER
→ AI20K
→ APPLICATION → PRODUCT
→ NEW QUESTIONS: VALUE / USER / EVIDENCE

Do not let this section become a full AI20K history.

### 03 — The Four-Week / Day-Based Journey
This is the temporal spine of the landing page.

Use a continuous timeline such as:
DAY 01 → DAY 02 → ... → DAY 27

Do not create fixed learning themes for Week 1, Week 2, Week 3, or Week 4.

The timeline should communicate breadth and progression by showing that different kinds of challenges appeared across the period.

Possible challenge categories:
- Product
- Business / Strategy
- UX / AI UX
- AI Systems / Agent Architecture
- Infrastructure / Platform
- Evaluation
- Human–AI Collaboration

The categories are a visual organizing layer, not a claim that each Day belongs to only one discipline.

Do not turn this into an exhaustive challenge portfolio. The timeline should show the shape of the journey, not force every challenge into a detailed case study.

Key narrative message:
> The learning was distributed across many different Days. The patterns only became clear when I looked back across the whole four-week experience.

### 04 — What Happened / Internship as a Learning Lab
Purpose: make the internship experience concrete without becoming a challenge-card gallery.

Show the recurring environment/process:

AI20K KNOWLEDGE / PRIOR MINDSET
→ BROAD OR AMBIGUOUS CHALLENGE
→ PERSONAL FRAMING
→ SCOPE DECISION
→ PRODUCT / TECHNICAL RESEARCH
→ PRODUCT EXPERIENCE OR PROTOTYPING WHEN POSSIBLE
→ AI AS SUPPORT
→ PERSONAL AUDIT / JUDGMENT
→ FEEDBACK / TEST / MENTOR INPUT
→ REFLECTION
→ NEXT ATTEMPT

Important:
This loop repeats across different challenge types. It is more truthful than pretending each week had a separate curriculum.

### 05 — What I Learned / Patterns Across the Whole Journey
These are **cross-cutting patterns**, not week-specific lessons.

Prioritize four major lessons:

#### 1. VALUE BEFORE TECHNOLOGY
The ability to build something is different from knowing whether it should be built, for whom, and why it matters.

#### 2. EVIDENCE BEFORE ASSUMPTION
Research, direct product experience, metrics, tests, and feedback can turn an opinion into a better-supported decision.

#### 3. HUMAN JUDGMENT OVER AI OUTPUT
The intern sets the direction, approach, and final judgment.
AI supports research, alternative perspectives, critique, and checking.

Visual:
MY INTENT
→ MY APPROACH
→ AI SUPPORT
→ RESEARCH / CRITIQUE
→ AUDIT
→ ADJUST
→ MY DECISION

#### 4. ALIGNMENT BEFORE OPTIMIZATION
Good execution on a misunderstood outcome can still miss the actual goal.

Supporting knowledge layer (secondary, not equal emphasis):
- agent harness / orchestration
- memory and context architecture
- RAG
- tools and workflows
- human-in-the-loop
- AI evaluation
- human-centered UI / AI UX
- sandbox / platform safety
- business, pricing, strategy, activation
- forward-deployed/customer communication

Do not render these as a buzzword wall. Group them into meaningful systems or clusters.

### 06 — What I Achieved
This section must be visibly identifiable because the brief explicitly asks for achievements.

Do not invent quantitative achievements.

Frame achievement across three real dimensions:

#### BREADTH OF EXPOSURE
Worked across different problem spaces rather than one narrow topic:
Product + Business + UX + AI Systems + Infrastructure + Evaluation + Human–AI Collaboration.

#### APPLIED PRACTICE
A more deliberate way to approach broad challenges:
FRAME
→ NARROW SCOPE
→ RESEARCH / EXPERIENCE
→ REASON
→ USE AI AS SUPPORT
→ AUDIT
→ DECIDE
→ REFLECT

#### BEHAVIOR CHANGE
- ask about value and outcome, not only implementation,
- seek evidence rather than rely only on assumptions,
- direct AI according to personal reasoning,
- distinguish completion from understanding/mastery,
- recognize the need to align on intended outcome earlier,
- connect engineering thinking with product and evaluation thinking.

Key statement:
Achievement is not only a list of artifacts. It is also what the intern became more capable of doing deliberately.

### 07 — A Major Turning Point / Alignment Before Optimization
This is a later moment in the journey, but do not label it as a fixed “Week 4 phase.”

Show:
- the intern had been trying to make answers more valuable through scoping, research, product experience, and personal judgment,
- a one-on-one mentor conversation revealed that the assumed outcome and intended outcome were not fully aligned,
- realization: strong reasoning and execution do not compensate for solving the wrong target.

Core visual statement:
GOOD EXECUTION
× WRONG OUTCOME
= WRONG RESULT

Then reveal:
ALIGNMENT BEFORE OPTIMIZATION

Vietnamese UI wording may use:
**Căn chỉnh đúng trước khi tối ưu.**

Do not frame the mentor or team as being at fault. This is a lesson about communication, problem framing, and expectation alignment.

### 08 — Evolution / Before vs Now
This is the visual climax.

Use a strong comparison, not a paragraph.

Possible transformation matrix:
- HOW DOES IT WORK? → WHY / FOR WHOM / HOW DO WE KNOW?
- Technology-first → Problem/value-aware
- Learn many interesting things → Learn selectively toward a goal
- Output → Outcome
- Assumption → Evidence
- Prototype works → Prototype + validation
- AI answer → Human judgment over AI output
- Complete the task → Understand and align on the intended outcome
- Learn once → Reflect, update, and repeat

Important:
Do not imply the earlier engineer mindset was bad. The evolved state combines engineering curiosity with product, evidence, human, and evaluation thinking.

### 09 — The Loop Continues / Where I Am Heading
End with the learning mechanism, then the future direction.

Primary loop:
EXPERIENCE
→ LEARN
→ REFLECT
→ SELECT
→ APPLY
→ FEEDBACK
→ UPDATE MINDSET
→ REPEAT

Then future direction:
**Human Evaluation × Development**

Frame as:
> A direction I want to grow toward: being able to build AI systems while also evaluating how reliably and meaningfully they work for humans.

Do not claim a finished role or mastery.

## Narrative rhythm
Alternate:
- large reflective statements,
- a Day-based temporal rail,
- category layers,
- diagrams/process visualizations,
- comparison states,
- small supporting annotations.

Avoid:
- fixed Week 1/2/3/4 learning themes,
- 10 consecutive text-heavy sections,
- a challenge-card gallery,
- equal visual weight for every technical term,
- turning the page into a CV/portfolio.
